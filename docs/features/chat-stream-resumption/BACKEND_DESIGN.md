# 后端设计

## 1. 模块职责

- `routers/conversations.py`：接收首次发送或恢复订阅请求，验证参数并返回 SSE。
- `services/conversations.py`：创建/查询生成任务、协调消息状态和终态持久化。
- 新增流式运行服务：执行模型生成、发布事件、设置超时和取消。
- 新增 Redis 事件仓储：追加、按序回放和阻塞读取 Redis Streams。
- `repositories/conversations.py`：生成任务及消息的事务性持久化。

## 2. 执行与订阅解耦

首次请求仅负责确保任务已启动。生成执行器在独立任务上下文中消费 `stream_with_retrieval()`，为每个事件分配连续序号并写入 Redis Streams；浏览器 SSE 生成器只负责回放和订阅，客户端断开不得取消执行器。

任务从启动起计时，达到 5 分钟必须写入 `timed_out` 终态、停止模型消费并更新助手消息。用户主动中断使用现有取消语义，但同时应停止执行器并发布 `interrupted` 终态。

## 3. 事件回放

订阅服务先读取大于 `afterSequence` 的缓存事件，再以 Redis 阻塞读取等待新事件。回放与实时订阅之间按单一游标衔接，避免漏事件或重复事件。读取到终态事件后关闭 SSE。

## 4. 错误处理

- 任务不属于当前用户：按不存在处理。
- `requestId` 已存在：复用同一任务，禁止再次调用模型。
- 任务终态：仅回放可用事件，不重启。
- 缓存过期：若数据库已有最终消息，返回明确的已完成恢复结果；若任务仍在生成，记录异常并返回不可恢复错误。
- Redis 或模型失败：将任务和助手消息置为失败，并发布统一错误终态（Redis 本身不可用时记录服务端日志）。

## 5. 可观测性

日志与任务记录必须包含 `requestId`、会话 ID、助手消息 ID、最后序号、开始/结束时间、终态和错误码；不得记录模型密钥或完整敏感提示词。
