# 需求与设计变更记录

## 2026-07-27：阶段 2A 双模式 SSE 契约实现

- **变更类型**：流式协议与前后端状态边界实现
- **变更状态**：实现中，自动化验证通过，待浏览器端联调
- **实现内容**：所有 SSE 事件增加 `mode`；预览事件不再要求持久化会话或消息 ID，正式会话事件保留这些 ID；前端严格验证模式与字段组合，并在预览模式下只维护本地消息。
- **后端边界**：预览和正式流的前置资源/权限校验在 `StreamingResponse` 建立前完成；预览与正式运行时未知异常均映射为稳定的 SSE `error`。
- **接口与数据影响**：修改现有两个流式接口的事件载荷，新增 `mode` 字段；无路由、数据库、迁移或依赖变更。
- **验证情况**：前端 Vitest 21 项通过；后端 SSE 协议测试 3 项通过；Python 编译检查和前端生产构建通过。

## 2026-07-27：未完成流式阶段按双运行上下文重排

- **变更类型**：已确认的实施计划与协议设计调整
- **变更状态**：已确认，尚未开始阶段 2A 编码
- **变更原因**：检查发现编辑页预览事件不含持久化消息标识，而前端将其按正式会话事件解析，导致预览链路在 `message_start` 或 `message_end` 阶段发生协议错误。
- **最终决定**：预览与正式聊天共享 Agent Runtime、SSE 事件类别和前端流基础设施，但通过 `mode: "preview" | "conversation"` 区分数据上下文。预览使用草稿配置和本地历史，不持久化；正式聊天只使用已保存配置和持久化会话。
- **阶段调整**：阶段 0/1 保持已完成；原阶段 2 拆分为 2A（双模式 SSE 契约）和 2B（后端生命周期与数据隔离），之后依序进行阶段 3（前端状态机）、阶段 4（页面联调）和阶段 5（回归验收）。
- **接口与数据影响**：计划调整当前未完成接口的 SSE 载荷语义；本次文档更新不修改路由、数据库结构、迁移或依赖。
- **验收要求**：预览事件可在无 `conversationId`/`messageId` 的条件下被正常消费，且不会创建或刷新正式会话；正式事件仍必须提供持久化标识。

## 2026-07-27：流式消息去重与确认清理修正

- **变更类型**：前端流式状态一致性修复
- **变更状态**：代码与自动化测试完成，待浏览器验收
- **变更原因**：新会话的首条流式问答完成后，本地临时消息与会话详情返回的持久化消息可能同时显示，造成重复；新请求在收到 `message_start` 前失败时，还可能误更新上一请求的助手消息状态。
- **变更内容**：以 `message_start` 返回的真实 ID 替换临时 ID；按消息 ID 合并详情与流式消息；完成消息对在详情确认后才清理；每次新发送前清空上一请求的真实 ID；SSE 事件在分发前做运行时结构校验。
- **影响的前端模块**：`api/chat.ts`、`features/chat/hooks/useStreamingChat.ts`、`features/chat/utils/mergeMessages.ts`、`pages/ChatPage.tsx`。
- **影响的后端模块**：无。
- **接口与数据结构**：不修改 SSE 路由、数据库表或迁移；前端严格消费既有的 `requestId`、`sequence` 与消息 ID 字段。
- **验证要求**：自动化测试覆盖 ID 替换、去重、确认清理、新请求早期失败及 SSE 非法事件拒绝；浏览器仍需验证新会话首条问答、历史会话续发和网络失败场景。
