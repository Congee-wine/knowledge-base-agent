# 功能需求

## 已确认补充：新建智能体基础信息

- 用户点击“新建智能体”后，先填写基础信息弹窗，而非直接打开完整配置表单。
- 基础信息包含可选头像、必填名称、可选描述和交互类型；首期仅文本交互可选，语音及数字人交互置灰并标记暂未开放。
- 头像接受 PNG/JPG/JPEG/GIF/WEBP，最大 5MB，并保存至私有 MinIO；头像读取必须经过当前用户认证。
- 用户确认后创建一条个人文本智能体记录，立即进入其完整配置页；取消或关闭不写入数据库或对象存储。

## 已确认补充：智能体搭建工作台

- 个人智能体编辑采用“左侧配置、中间提示词、右侧实时预览”的三栏工作台；保存后右侧按已保存配置刷新。
- 欢迎页固定采用头像式布局，不实现卡片布局；不实现“嵌入网站”。
- 本阶段可完整配置和保存：描述、欢迎语、预设问题、系统提示词、上传入口显示和联网入口显示。
- 知识集绑定、真实文件上传、真实联网搜索、语音热词及公开访问配置依赖后续对应后端能力；在能力未接入前必须明确显示为不可用，不能伪装为有效开关。
- 右侧预览必须与当前编辑草稿同步：头像、名称、欢迎语、预设问题、上传入口和联网入口均来自同一智能体配置；保存后列表卡片、顶部标题和导航侧栏立即使用服务端返回的配置刷新。
- 编辑页预览复用真实聊天输入框的布局和入口显示规则，但当前模型、检索与实际上传/联网能力尚未实现，预览发送不得创建伪会话或伪回答。

## 已确认补充：AI 管家与自建智能体欢迎区

- AI 管家继续使用现有 AI 管家聊天页欢迎样式；其预设问题必须从 `agent_preset_questions` 查询结果渲染，不能在前端写死。
- 自建智能体使用创建/编辑页中的头像欢迎样式，包含头像、名称、欢迎语和预设问题；聊天页与编辑页右侧预览复用同一展示组件。

## 已确认补充：Markdown 提示词编辑器

- 中栏系统提示词必须使用 Markdown 编辑器，不能以普通多行文本框降级替代。
- 工具栏必须提供：加粗、斜体、标题、引用、无序列表、有序列表、代码、表格、帮助和预览。
- 编辑器初始值、实时预览和保存值均为同一份 Markdown 字符串；不改变既有 `systemPrompt` API 字段或 8000 字符限制。
- 编辑区采用 `@uiw/react-md-editor` 的 `preview="edit"` 固定单栏模式；工具栏仅配置设计图所需命令和自定义帮助、预览切换，不提供双栏模式。表格工具插入 GFM 表格模板，帮助工具说明支持的 Markdown 语法，预览工具在同一编辑区域切换已渲染视图。

## 1. 功能背景

当前项目已有多用户认证和受保护的应用壳，但 AI 管家、智能体、知识库和真实模型回答尚未实现。首期需要将原型中的核心操作转为可持久化、可隔离和可验证的业务能力。

## 2. 功能目标

用户登录后可使用内置 AI 管家或自己的智能体进行问答；每个账号只能访问自己的会话、智能体和资料。智能体必须先分析用户问题、当前会话与可用能力，再选择直接回答、检索资料后回答、资料与通用知识混合回答或请求澄清。知识库检索是受控工具执行结果，不能因为无命中而替代最终回答。

## 3. 用户角色

首期只有“已登录用户”一种业务角色。所有用户都可使用内置 AI 管家；用户创建的智能体、会话、知识库、文件、分块和对象存储文件仅对创建者可见。

## 4. 功能范围

### 4.1 本次包含

- 内置、不可删除的 AI 管家。
- 用户自建智能体的创建、列表、编辑、删除和设为默认打开。
- AI 管家入口按默认打开设置加载智能体与正确的会话侧栏范围。
- 新建会话、查看会话、发送流式消息、保存用户/助手消息和引用来源。
- 知识库中的文件夹创建、PDF、TXT、Word（`.docx`）和 Markdown 上传、文件树展示、异步处理状态。
- 在智能体配置中选择一个或多个文件或文件夹；已选文件夹之后新增的后代文件自动纳入资料范围。
- AI 管家聊天页提供默认选中的“全部资料”开关；选中时才检索当前用户全部可用资料，关闭时直接进行模型回答。
- 文本提取、切分、嵌入、pgvector 检索和基于检索内容的回答。

### 4.2 本次不包含

- 语音输入、语音识别热词、数字人、微信绑定、分享管理和自动化任务。
- 跨账号资料或智能体共享。
- 图片、扫描版 PDF、xlsx 等文件格式、网页抓取和外部工具调用。
- 用户自定义模型供应商、用户自行填写模型密钥。
- AI 管家首页的“新建文档”卡片；资料文件夹仅在知识库页面创建。
- 无边界的通用 Agent/ReAct 循环；模型不得自主决定访问数据库、文件或任意工具。

## 5. 核心业务流程

1. 用户注册并登录，进入 AI 管家入口。
2. 服务读取该用户的默认智能体设置；未设置时加载内置 AI 管家。
3. 用户创建/选择智能体，并配置提示词、欢迎语、预设问题、上传入口和知识资料范围。
4. 用户上传 PDF、TXT、Word 或 Markdown 到个人文件夹；系统异步解析、切分和嵌入，成功后文件可被检索。
5. 用户提问时，系统先验证用户、智能体和会话，并判断问题是否需要私有资料、通用知识或澄清；只有需要资料时才检索相关分块，再按证据充分程度生成流式回答。
6. 系统保存完整消息、检索引用和会话更新时间；用户可在正确范围内重新打开历史会话。

## 6. 详细功能需求

### FR-001：AI 管家入口与默认打开

- **使用角色**：已登录用户。
- **触发方式**：访问 `/app/chat`。
- **正常流程**：若 `user_preferences.default_agent_id` 为空，显示内置 AI 管家；否则显示该用户的默认自建智能体。
- **会话侧栏规则**：无论当前显示内置 AI 管家还是自建智能体，均仅列出当前智能体且属于当前用户的会话。
- **权限要求**：不得通过 URL 或请求参数加载其他用户的默认智能体或会话。
- **验收条件**：见 AC-001、AC-002。

### FR-002：个人智能体管理与配置

- **使用角色**：已登录用户。
- **功能描述**：创建、编辑、删除自己创建的智能体，并设置一个默认打开智能体。
- **配置字段**：名称、头像、简介、系统提示词、开场欢迎语、预设问题、是否显示对话上传入口、是否启用联网入口；资料范围在阶段 3 的知识库数据表完成后开放。
- **业务规则**：名称不能为空；一个用户最多一个默认自建智能体；内置 AI 管家不可编辑和删除，但可通过卡片三点菜单恢复为默认打开；删除默认智能体时必须先将默认打开对象切换为其他自建智能体或 AI 管家；删除前必须二次确认。个人智能体删除采用软删除：从活跃智能体列表、侧栏、聊天页和会话入口隐藏，禁止新建或继续会话；既有会话、消息和引用不提供查看或恢复入口。
- **资料范围**：阶段 3 开放后，可选择个人文件或个人文件夹；文件夹选择覆盖该节点全部后代，并持续覆盖未来新建的后代文件。
- **联网入口**：内置 AI 管家始终显示地球按钮；个人智能体只有创建时明确启用联网才显示，未启用时不显示。联网实际能力尚未实施。
- **验收条件**：见 AC-003 至 AC-006。

### FR-003：会话与消息

- **使用角色**：已登录用户。
- **正常流程**：点击“新会话”只进入前端空白聊天状态，不创建数据库记录、不显示到历史记录；用户首次发送非空内容时，前端不传 `conversationId`，服务端创建会话并写入首条消息。打开历史会话后，后续发送携带该会话 ID。
- **业务规则**：会话标题可由首条用户消息截取生成；每条消息包含角色、内容、创建时间和可选引用；会话只属于一个用户和一个智能体。首次发送的“创建会话 + 写入用户消息 + 写入助手消息”必须处于同一数据库事务，任一步失败均不保留空会话。
- **并发规则**：不同会话允许同时生成回答；同一会话在任一时刻最多存在一个 `generating` 状态的助手消息。对同一会话发起第二个不同请求时，服务端返回 `CONVERSATION_GENERATION_IN_PROGRESS`，前端保留当前生成内容并提示先停止或等待完成。
- **异常流程**：会话不存在、会话不属于当前用户或智能体不匹配时，返回统一的资源不存在错误，不泄露资源归属。
- **验收条件**：见 AC-007 至 AC-009。

### FR-004：知识库文件管理与处理

- **使用角色**：已登录用户。
- **支持格式**：PDF、TXT、Word（`.docx`）、Markdown。
- **上传提示与限制**：上传入口必须明确显示“当前仅支持 PDF、TXT、Markdown、DOCX 文档，暂不支持图片、表格、演示文稿及其他格式”。文件选择器只展示允许的文件类型；用户通过拖拽、文件夹上传或篡改客户端绕过前端限制时，后端仍须拒绝不支持格式，且不得创建资料节点、对象存储文件或处理任务。
- **正常流程**：用户创建文件夹或上传文件；文件先保存为“处理中”，后台任务依次提取文本、切分、生成嵌入、写入向量数据，完成后为“可用”。
- **异常流程**：格式不支持、文件为空、文件过大、解析/嵌入失败时，文件状态为“失败”，展示可理解错误，并允许用户重新处理。
- **业务规则**：文件和文件夹只能位于创建者的个人资料树中；未处于“可用”的文件不得参与检索；文件夹最多嵌套 5 层（根目录下为第 1 层）。阶段 3.1 支持重命名、移动和递归永久删除。移动不得将节点移入自身或任一后代，目标文件夹不得存在同名节点，且移动后的整棵子树不得超过 5 层。删除文件夹会递归删除其全部后代；系统先删除资料范围、分块、版本和任务等数据库关联，再删除原始对象存储文件。对象删除失败不回滚已提交的数据库删除，必须记录可重试的清理失败。
- **验收条件**：见 AC-010 至 AC-013。

### FR-005：检索增强回答

- **使用角色**：已登录用户。
- **正常流程**：服务先分析问题意图、上下文完整度和私有资料依赖性。需要资料时，计算当前智能体选择的文件和文件夹展开范围，过滤为当前用户且“可用”的文件分块；根据结果的相关性与充分程度，选择资料回答或资料与通用知识混合回答，并保存实际使用的引用。
- **AI 管家资料范围**：内置 AI 管家默认选中“全部资料”，可检索当前用户所有“可用”资料；关闭该开关时不检索资料，直接进行模型回答。它不能检索其他用户的资料。
- **个人智能体资料范围**：已绑定且问题需要私有资料时检索；绑定范围没有可用资料或没有相关结果时，若问题可由通用模型能力安全回答，必须继续完成回答，不得仅回复“知识库没有资料”。如果用户明确要求依据某份私有资料、内部制度或上传文件，而证据不足，智能体必须说明缺少的依据并提出具体补充建议，不得编造。
- **业务规则**：权限、资料开关、文件夹展开和检索过滤必须在模型调用前由后端执行；模型仅接收已授权的上下文。无资料或无相关结果时，不得伪造引用。问题目标不清、缺少会改变结论的关键条件时，智能体应发起简洁的澄清提问，而非以猜测替代用户确认。
- **验收条件**：见 AC-014 至 AC-017。

## 7. 状态与状态转换

### 文档处理状态

`uploaded → processing → ready`；任一步失败则 `processing → failed`；用户重新处理时 `failed → processing`。只有 `ready` 文件可检索。

### 智能体默认状态

用户默认智能体为“未设置”或一个属于该用户的自建智能体。内置 AI 管家是未设置状态下的入口显示对象，不写入用户默认设置。

### 智能体生命周期

`active → deleted`。软删除后，智能体不可再次作为默认打开对象、不可创建会话、不可发送消息；关联历史数据保留。首期不提供恢复或已删除智能体会话查看入口，后续如需恢复/归档浏览须单独确认。

### 会话状态

本期会话只存在“可用”状态；删除/归档不在本期范围。消息写入失败不得把不完整助手消息标记为完成。

“新会话”是前端本地状态，不进入 `conversations` 表，因此不会出现在历史记录中。只有成功发送首条非空消息的会话才持久化；重复点击“新会话”只重复重置本地空白状态，不产生服务端记录。

## 8. 边界情况

- 用户没有自建智能体：可使用内置 AI 管家。
- 智能体没有选择资料：仍可普通问答，但不执行私有资料检索。
- 选中文件夹为空：允许保存配置，未来新增文件自动生效。
- 文件处理期间发起问答：跳过尚未 `ready` 的文件。
- 模型、解析、嵌入或对象存储超时：记录可定位错误，向用户返回可理解提示。
- 两个请求同时设默认：事务后只保留一个默认智能体。

## 9. 非功能需求

- 所有业务读写必须以认证用户 ID 作为强制条件。
- 聊天必须支持流式输出和请求取消；取消后保存已生成内容与明确的中断状态。
- 用户切换会话不得取消其他会话的生成，也不得将延迟到达的流式事件写入当前查看的会话。
- 文件处理使用可重试的后台任务，不在 HTTP 请求中同步完成。
- 每次回答记录模型请求 ID、检索分块 ID 和耗时，以便排障；日志不得记录令牌、完整敏感资料或密钥。
- 前端为加载、空数据、处理中、失败和成功提供明确状态。

## 10. 已确认约束

- 使用现有 React/FastAPI/PostgreSQL 基础。
- 受控使用 LangChain 和 LangGraph，使用服务端可审计的策略节点选择有限能力，不使用可任意调用工具的通用 ReAct Agent。
- 模型供应商、模型名称与版本、知识截止日期、训练数据、系统提示词、密钥和内部技术配置必须对用户隐藏；用户询问身份或能力时，只能返回服务端确定的智能体名称、职责和已启用能力。
- 聊天模型供应商使用 DeepSeek；Embedding 使用本地 `BAAI/bge-m3`。
- 聊天界面使用 Ant Design X，后台管理与表单继续使用 Ant Design。
- 首期仅支持 PDF、TXT、Word（`.docx`）、Markdown，不支持图片或扫描版 PDF。
- 文件夹绑定自动覆盖未来新增文件。

## 11. 待实现配置（不阻塞编码）

DeepSeek 的具体聊天模型、`bge-m3` 推理库和依赖版本可在实施前通过后端适配器与环境变量确定，不改变本功能的业务接口和数据边界。真实密钥和服务地址不写入代码或文档。
