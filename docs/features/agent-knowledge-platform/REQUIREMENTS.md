# 功能需求

## 1. 功能背景

当前项目已有多用户认证和受保护的应用壳，但 AI 管家、智能体、知识库和真实模型回答尚未实现。首期需要将原型中的核心操作转为可持久化、可隔离和可验证的业务能力。

## 2. 功能目标

用户登录后可使用内置 AI 管家或自己的智能体进行问答；每个账号只能访问自己的会话、智能体和资料。智能体能从用户明确选择的文件/文件夹中检索资料并在回答中提供来源。

## 3. 用户角色

首期只有“已登录用户”一种业务角色。所有用户都可使用内置 AI 管家；用户创建的智能体、会话、知识库、文件、分块和对象存储文件仅对创建者可见。

## 4. 功能范围

### 4.1 本次包含

- 内置、不可删除的 AI 管家。
- 用户自建智能体的创建、列表、编辑、删除和设为默认打开。
- AI 管家入口按默认打开设置加载智能体与正确的会话侧栏范围。
- 新建会话、查看会话、发送流式消息、保存用户/助手消息和引用来源。
- 知识库中的文件夹创建、PDF、TXT、Word（`.docx`）和 Markdown 上传、文件树展示、异步处理状态。
- 在智能体配置中选择一个或多个文件或文件夹；已选文件夹之后新增的后代文件自动纳入资料范围。
- 文本提取、切分、嵌入、pgvector 检索和基于检索内容的回答。

### 4.2 本次不包含

- 语音输入、语音识别热词、数字人、微信绑定、分享管理和自动化任务。
- 跨账号资料或智能体共享。
- 图片、扫描版 PDF、xlsx 等文件格式、网页抓取和外部工具调用。
- 用户自定义模型供应商、用户自行填写模型密钥。
- 通用 Agent/ReAct 循环；模型不得自主决定访问数据库、文件或任意工具。

## 5. 核心业务流程

1. 用户注册并登录，进入 AI 管家入口。
2. 服务读取该用户的默认智能体设置；未设置时加载内置 AI 管家。
3. 用户创建/选择智能体，并配置提示词、欢迎语、预设问题、上传入口和知识资料范围。
4. 用户上传 PDF、TXT、Word 或 Markdown 到个人文件夹；系统异步解析、切分和嵌入，成功后文件可被检索。
5. 用户提问时，系统先验证用户、智能体、会话和资料范围，再检索相关分块并流式生成回答。
6. 系统保存完整消息、检索引用和会话更新时间；用户可在正确范围内重新打开历史会话。

## 6. 详细功能需求

### FR-001：AI 管家入口与默认打开

- **使用角色**：已登录用户。
- **触发方式**：访问 `/app/chat`。
- **正常流程**：若 `user_preferences.default_agent_id` 为空，显示内置 AI 管家；否则显示该用户的默认自建智能体。
- **会话侧栏规则**：无论当前显示内置 AI 管家还是自建智能体，均仅列出当前智能体且属于当前用户的会话。
- **权限要求**：不得通过 URL 或请求参数加载其他用户的默认智能体或会话。
- **验收条件**：见 AC-001、AC-002。

### FR-002：个人智能体管理与配置

- **使用角色**：已登录用户。
- **功能描述**：创建、编辑、删除自己创建的智能体，并设置一个默认打开智能体。
- **配置字段**：名称、头像、简介、系统提示词、开场欢迎语、预设问题、是否显示对话上传入口、资料范围。
- **业务规则**：名称不能为空；一个用户最多一个默认自建智能体；内置 AI 管家不可编辑和删除；删除默认智能体时必须先清空默认设置；删除前必须二次确认。个人智能体删除采用软删除：从活跃智能体列表隐藏，禁止新建或继续会话，但既有会话、消息和引用不物理删除。
- **资料范围**：可选择个人文件或个人文件夹；文件夹选择覆盖该节点全部后代，并持续覆盖未来新建的后代文件。
- **验收条件**：见 AC-003 至 AC-006。

### FR-003：会话与消息

- **使用角色**：已登录用户。
- **正常流程**：用户可在当前允许的会话侧栏中新建、打开和继续会话；新建会话归属当前智能体与当前用户。
- **业务规则**：会话标题可由首条用户消息截取生成；每条消息包含角色、内容、创建时间和可选引用；会话只属于一个用户和一个智能体。
- **异常流程**：会话不存在、会话不属于当前用户或智能体不匹配时，返回统一的资源不存在错误，不泄露资源归属。
- **验收条件**：见 AC-007 至 AC-009。

### FR-004：知识库文件管理与处理

- **使用角色**：已登录用户。
- **支持格式**：PDF、TXT、Word（`.docx`）、Markdown。
- **正常流程**：用户创建文件夹或上传文件；文件先保存为“处理中”，后台任务依次提取文本、切分、生成嵌入、写入向量数据，完成后为“可用”。
- **异常流程**：格式不支持、文件为空、文件过大、解析/嵌入失败时，文件状态为“失败”，展示可理解错误，并允许用户重新处理。
- **业务规则**：文件和文件夹只能位于创建者的个人资料树中；未处于“可用”的文件不得参与检索；删除和移动功能不在本期实现。
- **验收条件**：见 AC-010 至 AC-013。

### FR-005：检索增强回答

- **使用角色**：已登录用户。
- **正常流程**：服务计算当前智能体选择的文件和文件夹展开范围，过滤为当前用户且“可用”的文件分块；将召回结果构造成上下文，交由模型生成流式回答，并保存引用。
- **AI 管家资料范围**：内置 AI 管家默认可检索当前用户所有“可用”资料；它不能检索其他用户的资料。
- **业务规则**：权限、文件夹展开和检索过滤必须在模型调用前由后端执行；模型仅接收已授权的上下文。无资料或无相关结果时，模型应明确说明没有找到相关资料，不得伪造引用。
- **验收条件**：见 AC-014 至 AC-017。

## 7. 状态与状态转换

### 文档处理状态

`uploaded → processing → ready`；任一步失败则 `processing → failed`；用户重新处理时 `failed → processing`。只有 `ready` 文件可检索。

### 智能体默认状态

用户默认智能体为“未设置”或一个属于该用户的自建智能体。内置 AI 管家是未设置状态下的入口显示对象，不写入用户默认设置。

### 智能体生命周期

`active → deleted`。软删除后，智能体不可再次作为默认打开对象、不可创建会话、不可发送消息；关联历史数据保留。首期不提供恢复或已删除智能体会话查看入口，后续如需恢复/归档浏览须单独确认。

### 会话状态

本期会话只存在“可用”状态；删除/归档不在本期范围。消息写入失败不得把不完整助手消息标记为完成。

## 8. 边界情况

- 用户没有自建智能体：可使用内置 AI 管家。
- 智能体没有选择资料：仍可普通问答，但不执行私有资料检索。
- 选中文件夹为空：允许保存配置，未来新增文件自动生效。
- 文件处理期间发起问答：跳过尚未 `ready` 的文件。
- 模型、解析、嵌入或对象存储超时：记录可定位错误，向用户返回可理解提示。
- 两个请求同时设默认：事务后只保留一个默认智能体。

## 9. 非功能需求

- 所有业务读写必须以认证用户 ID 作为强制条件。
- 聊天必须支持流式输出和请求取消；取消后保存已生成内容与明确的中断状态。
- 文件处理使用可重试的后台任务，不在 HTTP 请求中同步完成。
- 每次回答记录模型请求 ID、检索分块 ID 和耗时，以便排障；日志不得记录令牌、完整敏感资料或密钥。
- 前端为加载、空数据、处理中、失败和成功提供明确状态。

## 10. 已确认约束

- 使用现有 React/FastAPI/PostgreSQL 基础。
- 受控使用 LangChain 和 LangGraph，不使用通用 ReAct Agent。
- 聊天模型供应商使用 DeepSeek；Embedding 使用本地 `BAAI/bge-m3`。
- 聊天界面使用 Ant Design X，后台管理与表单继续使用 Ant Design。
- 首期仅支持 PDF、TXT、Word（`.docx`）、Markdown，不支持图片或扫描版 PDF。
- 文件夹绑定自动覆盖未来新增文件。

## 11. 待实现配置（不阻塞编码）

DeepSeek 的具体聊天模型、`bge-m3` 推理库和依赖版本可在实施前通过后端适配器与环境变量确定，不改变本功能的业务接口和数据边界。真实密钥和服务地址不写入代码或文档。
