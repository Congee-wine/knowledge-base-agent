# 前端设计

## 1. 设计目标和范围

在现有 `/app/*` 受保护路由和 `AppLayout` 内实现聊天、智能体管理、智能体配置、知识库文件树。页面只负责组合与交互；请求、流式协议和错误转换放入 `api/`，服务器状态由 React Query 管理。聊天展示使用 Ant Design X，后台管理和表单继续使用已有 Ant Design。

## 2. 涉及页面与路由

| 页面 | 路由 | 页面职责 | 访问条件 |
| --- | --- | --- | --- |
| AI 管家入口 | `/app/chat` | 根据默认设置加载内置或自建智能体，展示聊天与当前智能体会话侧栏 | 已登录 |
| 指定智能体聊天 | `/app/chat/agents/:agentId` | 直接打开本人智能体；会话侧栏只显示该智能体会话 | 已登录且拥有智能体 |
| 智能体列表 | `/app/agents` | 展示内置 AI 管家和本人智能体，创建/编辑/删除/设默认 | 已登录 |
| 智能体配置 | `/app/agents/:agentId/edit`、`/app/agents/new` | 编辑智能体字段、资料范围和上传入口 | 已登录且拥有智能体 |
| 知识库 | `/app/knowledge-bases` | 展示个人文件树、创建文件夹、上传及处理状态 | 已登录 |

## 3. 页面结构

### 聊天页

- 欢迎态不显示当前智能体标题栏；右上角仅显示“新会话”和“历史记录”文字操作，历史记录默认收起。
- 欢迎区是纯白画布，显示左对齐的通用问候语和纵向编号预设问题。认证数据尚无昵称字段，不伪造用户姓名。
- 主区：欢迎态、消息列表、引用卡片、流式输出和输入框。
- 右侧：新建会话与会话列表；始终只请求和展示当前智能体的会话，前端不得混入其他智能体会话。
- 输入框：发送、取消生成；AI 管家显示默认选中的“全部资料”开关，关闭时不检索资料；上传入口对 AI 管家始终显示、对个人智能体仅在 `allowConversationUpload=true` 时显示；麦克风对所有智能体显示；地球联网入口对 AI 管家始终显示、对个人智能体仅在 `allowNetworkAccess=true` 时显示；Agent 模式入口始终显示。
- “全部资料”在 AI 管家首次进入时默认选中。Agent 模式、联网、上传和麦克风尚未具备实际能力，当前点击给出“功能暂未支持”提示，不创建伪请求或伪结果。
- 不展示“新建一个文档”卡片；创建资料文件夹和上传资料均通过知识库页面完成。

### 智能体列表与配置页

- 列表卡片显示名称、简介、所有者标识、默认标签和操作菜单。
- 内置 AI 管家卡片只能打开，不能编辑/删除。
- 配置页使用分区表单：基础信息、对话行为、资料范围；右侧为只读预览。
- 资料范围选择器复用知识库树，节点以“文件”或“文件夹”类型显示；选中文件夹时展示“将自动包含后续新增文件”的说明。

### 知识库页

- 文件夹面包屑、树/网格切换、上传按钮和创建文件夹按钮。
- 每个文件显示格式、处理状态、失败原因摘要和重新处理操作。
- 本期不提供删除或移动操作，避免展示不可用的入口。

## 4. 组件设计

| 组件 | 类型 | 职责 | 状态来源 |
| --- | --- | --- | --- |
| `ChatPage` | 页面 | 组合聊天、会话与输入区 | 路由与 React Query |
| `ConversationSidebar` | 业务组件 | 新建/选择当前智能体会话 | 会话查询 |
| `MessageList`、`CitationList` | 展示组件 | 渲染消息、流式片段和引用 | 页面本地流式状态 |
| `ChatComposer` | 表单组件 | 校验并发送消息、取消请求 | 本地表单状态 |
| `AgentListPage`、`AgentCard` | 页面/展示组件 | 管理本人智能体 | 智能体查询 |
| `AgentEditorPage`、`AgentForm` | 页面/表单组件 | 编辑配置和资料选择 | 表单状态、资料树查询 |
| `KnowledgeBasePage`、`KnowledgeTree` | 页面/业务组件 | 浏览资料、上传和显示处理状态 | 资料树查询 |

聊天区域优先使用 Ant Design X 的 `Welcome`、`Prompts`、`Bubble`、`Sender`、`Conversations`、`Sources` 与 `@ant-design/x-markdown`；不使用其数据流 SDK，仍由自有 SSE 客户端、React Query 和业务 API 管理会话、鉴权与引用数据。

## 5. 状态设计

- React Query：当前入口解析、智能体列表/详情、会话列表/详情、资料树、文件处理状态。
- Zustand：仅保留已有认证用户状态；不将会话消息、表单或资料树放入全局 Store。
- 页面本地状态：当前会话 ID、正在生成的临时助手消息、是否取消、配置表单脏状态、上传进度。当前会话 ID 已在 AI 管家页实现；其余状态按对应功能阶段接入。
- URL：指定智能体和指定会话使用路径/查询参数表达，保证刷新后可恢复。

## 6. 数据请求与流式处理

1. 进入 `/app/chat` 时请求入口解析结果和当前智能体的会话列表。
2. 进入指定智能体页面时请求智能体详情，失败的 404 统一显示“智能体不存在或无权访问”。
3. 点击“新会话”只清空页面本地当前会话 ID 和输入内容，不发送请求、不刷新历史列表。当前阶段发送消息时，若当前会话 ID 为空，则调用非流式延迟创建消息接口，不传 `conversationId`；否则携带当前会话 ID。
4. 当前非流式发送采用乐观更新：提交后立即清空输入框、展示本地用户消息和“正在回复”气泡；成功后将接口返回的两条消息写入 React Query 对应会话详情缓存，失败则移除临时消息并恢复输入。会话列表后台刷新但不阻塞消息显示；不因发送消息重新请求完整会话详情。接入模型后改为请求 SSE 延迟发送接口：收到首个会话 ID 后刷新历史列表并选中会话；收到 `token` 事件追加临时消息；收到 `citation` 事件更新引用；收到 `complete` 后失效会话与消息查询；收到 `error` 显示错误并保留可重试的用户输入。
5. 取消时中止 `AbortController`；后端返回的最终状态决定是否保留部分回答。
6. 上传成功后轮询/订阅文件处理状态；状态变为 `ready` 或 `failed` 时刷新资料树。

## 7. 关键交互规则

- “设为默认打开”成功后刷新入口解析；AI 管家入口立即显示新默认智能体。
- 删除当前默认智能体前必须先取消默认；后端仍是最终校验者。
- 选择文件夹无需枚举和勾选所有后代文件；前端只提交该文件夹节点 ID。
- 无论内置 AI 管家还是自建智能体被显示，会话侧栏均不得展示其他智能体会话。
- 空白新会话不属于服务端会话列表；只有首条消息成功后，响应中的会话 ID 才成为当前会话并刷新历史列表。

## 8. 页面状态

| 区域 | 初始/加载 | 空状态 | 失败状态 |
| --- | --- | --- | --- |
| 会话侧栏 | 骨架屏 | “还没有会话”与新建按钮 | 可重试提示 |
| 智能体列表 | 骨架卡片 | 仅展示内置 AI 管家及创建入口 | 可重试提示 |
| 资料树 | 骨架树 | “暂无资料”与上传入口 | 显示失败文件与重新处理按钮 |
| 聊天区 | 欢迎语；打开未缓存的历史会话时显示左右交错的消息骨架屏 | 无历史消息时显示预设问题 | 流式中断/模型失败提示 |
