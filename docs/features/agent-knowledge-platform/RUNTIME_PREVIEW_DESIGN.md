# 共享智能体运行与编辑页实时预览设计

## 文档状态

已确认，待实现。

## 1. 目标与范围

让编辑工作台右侧成为可交互的智能体沙盒：它使用当前未保存的完整草稿配置生成真实回答；保存后，AI 管家或指定智能体聊天页使用同一运行逻辑和已保存配置生成同类回答。

首期包含：DeepSeek 文本问答、系统提示词、有限消息历史、正式会话持久化、无持久化预览、SSE 流式通信和最终答案增量输出。受控处理思路摘要延后至知识库与引用能力稳定后实施。

首期不包含：知识库检索、真实联网搜索、对话文件上传、语音、Agent 工具、SSE 流式输出。现有入口仍按配置显示，但点击只提示未接入。

## 2. 两个入口与一个运行核心

```text
编辑页预览
  完整表单草稿 + 本地预览历史
  -> Preview Service（只读权限校验，不持久化）
  -> Agent Runtime Service
  -> DeepSeek Adapter
  -> 返回预览回答

正式聊天页
  数据库已保存智能体 + 正式会话历史
  -> Conversation Service（创建或读取会话、持久化消息）
  -> Agent Runtime Service
  -> DeepSeek Adapter
  -> 返回正式回答
```

`Agent Runtime Service` 是唯一允许组装模型输入和调用 DeepSeek 的业务层。它不依赖 HTTP 对象、不直接执行 SQL、不知道调用来自预览还是正式聊天。

运行结果从一开始为后续扩展预留最终回答与系统执行事件的边界；阶段 A 只输出最终回答和简单生成状态。阶段 D 再增加 `reasoningSummary`，阶段 B/C 增加 `executionSteps` 与引用。不得将模型完整原始思维链直接作为普通消息内容展示。

## 3. 后端设计

### 3.1 模块职责

| 模块 | 职责 |
| --- | --- |
| `integrations/deepseek.py` | 使用 `httpx` 调用 DeepSeek OpenAI 兼容 Chat Completions；处理超时、状态码和响应格式。 |
| `services/agent_runtime.py` | 将系统提示词、历史和本次用户消息转换为模型消息；执行长度限制；返回回答文本。 |
| `services/agent_preview.py` | 校验当前用户拥有 `agentId`，验证草稿字段，调用运行服务；禁止调用任何写 Repository。 |
| `services/conversations.py` | 正式聊天读取数据库智能体、调用运行服务，并持久化用户消息和助手消息。 |
| `routers/agents.py` | 声明预览路由、参数校验和认证依赖。 |
| `routers/conversations.py` | 将当前回显消息实现替换为正式运行服务调用。 |

### 3.2 配置与模型输入

模型输入按固定顺序构成：

1. 系统消息：智能体 `systemPrompt`，为空时使用平台最小安全基线。
2. 历史消息：最多最近 10 条、每条最多 4,000 字符，总长度受服务端令牌预算限制。
3. 当前用户消息：去首尾空格，长度 1–4,000 字符。

首期不会将名称、欢迎语、预设问题、上传/联网开关写入模型提示词；它们分别属于 UI 展示和能力开关。`systemPrompt` 才是首期回答行为的配置来源。阶段 A 不将模型推理内容返回前端；后续受控摘要与最终答案必须分开返回。

### 3.3 正式聊天持久化

- 首次发送仍采用延迟建会话：先验证智能体可用，再创建会话和用户消息。
- DeepSeek 成功后写入 `assistant` 消息，状态为 `complete`。
- DeepSeek 失败时保留用户消息；助手消息写入 `failed` 或返回统一错误，具体以现有消息状态结构的最小改动为准。
- 正式入口永远读取数据库中的智能体配置，不接收前端草稿。

### 3.4 无持久化预览

- 预览请求必须携带 `agentId`、完整 `draftAgent`、`content` 和本地历史。
- 后端只验证：当前用户能编辑该个人智能体、草稿字段符合与 PATCH 相同的长度/枚举规则、历史消息格式正确。
- 请求不创建会话，不写 `agents`、`conversations`、`messages`、引用或审计业务记录。
- 预览采用请求中的草稿 `systemPrompt`；因此未保存改动会立即影响下一条回答。
- 配置变更不会重新生成旧回答；前端提供“重置预览”让用户显式清空本地历史。

### 3.5 错误、安全与成本

- `DEEPSEEK_API_KEY` 仅保留在后端环境变量；不得下发浏览器或记录到日志。
- DeepSeek 超时、上游 401/429、网络错误和不合法响应统一转换为 `MODEL_UNAVAILABLE` 或 `MODEL_RESPONSE_INVALID`。
- 预览接口设置更严格的频率限制和历史长度限制，防止编辑页无限消耗模型额度。
- 不实现 RAG 时，模型不接收任何用户私有文件内容；不实现联网时，模型不具备外部搜索工具。

## 4. API 设计

### POST `/api/agents/{agentId}/preview/messages`

认证：Bearer access token；仅当前用户拥有的个人智能体可调用。

请求：

```json
{
  "content": "请介绍你的职责",
  "draftAgent": {
    "name": "销售助手",
    "description": "回答销售问题",
    "avatarKey": "agent-avatars/example.png",
    "systemPrompt": "你是一名专业销售助手。",
    "welcomeMessage": "你好，我是销售助手。",
    "presetQuestions": ["介绍产品优势"],
    "allowConversationUpload": true,
    "allowNetworkAccess": false,
    "interactionType": "text"
  },
  "history": [
    { "role": "user", "content": "你好" },
    { "role": "assistant", "content": "你好，请问有什么可以帮助你？" }
  ]
}
```

成功响应：

```json
{
  "assistantMessage": {
    "role": "assistant",
    "content": "……",
    "generationStatus": "complete"
  }
}
```

响应不包含 `conversationId`、`messageId`，以保证调用方不会误以为预览已持久化。

### 正式聊天 API 调整

保留 `POST /api/conversations/messages` 的请求和响应契约；将内部的回显实现替换为共享运行服务。这样正式聊天页不需要因首期 DeepSeek 接入而重做 URL 与会话状态模型。

## 5. 前端设计

### 5.1 组件边界

| 组件/Hook | 职责 |
| --- | --- |
| `ChatMessageList` | 正式聊天和预览共用的消息渲染；阶段 A 显示生成状态和流式答案，后续扩展推理摘要和执行步骤区域。 |
| `ChatComposerSurface` | 正式聊天和预览共用的输入与入口可见性规则。 |
| `usePreviewChat` | 仅维护右栏本地消息、发送状态、失败重试和重置。 |
| `AgentEditorPreview` | 组合 `previewAgent`、欢迎区、消息列表、输入框和重置预览操作。 |
| `useSendMessage` | 保持正式会话缓存与持久化流程，不与预览状态混用。 |

### 5.2 交互流程

1. 用户修改编辑表单，`previewAgent` 立即更新；欢迎区和入口立即变更。
2. 用户点击预设问题或输入文本，前端将本地历史和完整草稿发送到预览 API。
3. 成功后追加本地用户消息与助手消息，并增量更新最终答案；不失效会话列表、不更新 React Query 正式会话缓存。
4. 失败后保留输入与历史，显示错误和重试操作。
5. 用户点击“重置预览”时只清空本地消息；离开编辑页也自动丢弃预览历史。
6. 用户点击保存后，保存与预览是两个独立动作：保存更新数据库配置；既有预览历史保持，但下一条预览消息使用保存后的同一草稿值。

## 6. 验收标准

- 未保存的系统提示词从“销售助手”改为“法律助手”后，下一条预览回答遵循新角色；刷新页面前不需要保存。
- 阶段 D 启用后，预览和正式聊天的助手消息均可展开查看简短处理思路摘要；摘要与最终回答分区展示，摘要不替代最终结论。
- 预览发送后，数据库中 `conversations`、`messages` 数量不增加。
- 正式聊天发送后，数据库中会话和两条消息正确增加，且回答由相同 DeepSeek 运行服务生成。
- 用户 A 不能调用用户 B 的智能体预览接口；内置 AI 管家不可通过编辑预览接口修改或运行草稿。
- 首期点击上传、联网、知识库/Agent 入口不发起外部请求，并显示“功能暂未接入”。
- 缺失模型密钥、模型超时或上游限流时，不显示伪造助手回答，且用户输入可重试。

## 7. 实施阶段与后续能力

### 阶段 A：下一项实现

实现 DeepSeek 适配器、共享运行服务、正式文本问答、无持久化预览、SSE 流式通信、最终答案增量输出、取消、幂等和断线恢复。新增生产依赖预计为 `httpx`；详细协议与数据变更以 `STREAMING_RUNTIME_PLAN.md` 为准。

### 阶段 B：知识库真实能力

在阶段 A 通过真实模型联调后实施。需要先完成资料树、私有对象上传、异步解析、分块、`bge-m3` 向量化、pgvector 检索和智能体资料范围绑定；完成后才将检索上下文接入同一运行服务。知识库不是单独打开一个按钮，而是一条完整的数据处理与权限链路。

### 阶段 C：真实联网能力

在知识库能力稳定后实施。需要单独确认搜索供应商、允许域名、超时、查询次数与费用上限、结果清洗、网页内容安全策略及引用展示。联网结果必须作为受控上下文传给模型，不能给予模型任意网络访问权。

### 阶段 D：真实对话文件上传

在知识库文件处理链路稳定后实施。对话上传与“永久加入知识库”是两种不同生命周期：前者需要临时对象、会话绑定、过期清理和按会话检索；后者复用知识库文件处理与长期索引。两者不能混为一个上传接口。

### 阶段 E：流式与取消

当阶段 A–C 的执行事件、引用、错误处理和持久化经过验收后，同时为正式聊天和预览增加受控的处理思路摘要；预览仍不持久化，正式聊天需要处理摘要的保存范围与失败状态。

- 预览接口的每用户频率上限与并发上限。

- 阶段 D 的临时文件保留时长和是否允许用户将对话附件转存到知识库。
