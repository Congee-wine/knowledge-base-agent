# 实施计划

## 实施原则

- 每个阶段开始前，在开发记录中说明目标、模块、方案原因、风险和验证方式。
- 每阶段结束后只按实际验证结果更新状态，不把未联调功能标记为完成。
- 路由只处理 HTTP；业务规则在 Service；SQL 在 Repository；LangGraph 节点只编排 Service。
- 每次数据结构变化都通过版本化迁移，禁止继续向启动初始化函数追加业务表 DDL。

## 阶段 1：运行基础设施与数据迁移

### 目标

建立能安全承载后续业务的配置、迁移、对象存储、任务队列和模型适配边界。

### 涉及模块

- `backend/core`、`backend/integrations`、`backend/repositories`、`backend/workers`。
- PostgreSQL/pgvector、MinIO、Redis、DeepSeek、`bge-m3`。

### 实施步骤

1. 引入版本化迁移工具，为现有认证表建立基线，再创建智能体与知识库业务迁移。
2. 将数据库连接、对象存储、Redis、DeepSeek 与 BGE 配置集中到类型化配置模块；仅记录环境变量名称。
3. 封装对象存储、Redis 任务投递、DeepSeek Chat Model、BGE Embedding 的适配接口，并提供本地开发错误提示。
4. 建立 Worker 进程入口和任务状态模型；此阶段只验证任务可投递和执行，不实现完整解析流程。

### 选择理由

这些依赖是会话、文件和 RAG 的共同基础。先建立边界可以避免把第三方 SDK、密钥和网络错误散落到路由或工作流节点中。

### 风险与验证

- 风险：本地 Docker/服务未启动、模型权重下载失败、Windows 环境依赖差异。
- 验证：迁移可在空数据库升级；健康检查能识别必要服务；Worker 能执行无副作用测试任务；配置缺失时错误可定位。

## 阶段 2：智能体、默认打开与会话数据层

### 目标

完成 AI 管家、个人智能体、默认打开和“当前智能体会话隔离”的数据库与 API，不接入真实模型。

### 实施步骤

1. 创建智能体、偏好、会话、消息和引用表及索引；写入内置 AI 管家种子记录。
2. 实现 Repository 与 Service 的所有权校验、默认设置事务和软删除。
3. 实现 API-001 至 API-007，并用回显/测试回答验证会话读写。
4. 实现智能体列表、配置、默认打开和会话侧栏前端页面；先用普通消息渲染验证交互。

### 后端/AI说明

此阶段不需要 LangGraph。先验证“用户 A 永远不能看到用户 B 的资源”“每个智能体只显示自己的会话”这两个最重要的业务边界；AI 流程将在阶段 4 接入。

### 风险与验证

- 风险：软删除后默认设置和旧会话状态不一致。
- 验证：多用户越权接口测试、并发设置默认测试、软删除数据保留测试、前端构建。

## 阶段 3：文字资料与本地向量索引

### 目标

实现 PDF、TXT、DOCX、Markdown 的个人资料树、异步处理和 `bge-m3` 向量写入。

### 实施步骤

1. 创建资料节点、文件版本、处理任务、分块和资料范围关联表。
2. 实现文件夹、上传、状态查询和失败重试 API；原文件写入私有 MinIO bucket。
3. Worker 提取文字：PDF 使用 PyMuPDF，DOCX 使用 `python-docx`，TXT/Markdown 使用本地读取。
4. 使用 LangChain 文本切分器切分内容，Worker 本地调用 `bge-m3` 批量生成向量，写入 pgvector。
5. 实现智能体文件/文件夹范围配置与递归展开；验证新文件自动进入已选文件夹范围。

### 后端/AI说明

`bge-m3` 只负责“把文字转为向量”，不生成回答。上传处理必须放 Worker，因为模型加载、解析和批量向量化会阻塞 Web 请求。

### 风险与验证

- 风险：文档解析异常、BGE 内存不足、重复任务写入重复分块。
- 验证：四种格式处理测试、失败重试测试、文件夹自动纳入测试、向量检索最小集测试。

## 阶段 4：LangGraph RAG 聊天与流式界面

### 目标

接入 DeepSeek、LangChain、LangGraph、SSE 和 Ant Design X，完成真实可引用的 RAG 问答。

### 实施步骤

1. 实现固定图：加载会话上下文 → 检索允许分块 → 生成回答 → 保存结果。
2. 用 LangChain 适配 DeepSeek 和 `bge-m3`；检索前由 Service 完成用户、智能体与资料范围校验。
3. 用 FastAPI 将 LangGraph 事件转换为 SSE，支持状态、token、引用、完成和错误事件。
4. 用 Ant Design X 的 `Welcome`、`Prompts`、`Bubble`、`Sender`、`Conversations`、`Sources` 与流式 Markdown 渲染聊天页。
5. 完成取消生成、无召回、模型失败和引用展示。

### 后端/AI说明

LangGraph 只编排固定流程；它不自行选择数据库、文件或工具。DeepSeek 只接收后端已经授权的少量检索文本，因此模型不能越过资料范围。

### 风险与验证

- 风险：SSE 中断、模型超时、引用与最终回答不同步。
- 验证：流式接口测试、取消测试、越权资料不进入模型上下文测试、浏览器端到端测试。

## 阶段 5：质量、性能和验收

### 目标

依据 `AC-001` 至 `AC-017` 完成跨层验证，并处理首期上线前风险。

### 实施步骤

1. 执行 Python 类型/编译、前端类型/构建、服务单元测试、接口测试和文件处理集成测试。
2. 使用真实但非敏感样本资料验证召回、引用、延迟和失败恢复。
3. 评估 pgvector 索引：先精确检索，数据规模达到阈值后基准测试 HNSW。
4. 审查日志、对象存储权限、环境变量、错误信息和跨账号访问边界。

### 完成条件

所有已确认验收项有对应验证证据；未验证或明确延期的项保留在项目状态和开发日志中。
