# 实施计划

## 2026-07-27：当前执行计划（知识库阶段）

### 已完成的前置条件

- 正式聊天已恢复为直接 SSE；用户已完成正常回答和停止生成的浏览器验收。
- Redis/RQ 聊天事件缓冲与断线续流曾进行实现尝试，但未达到端到端验收标准，相关代码已撤回并明确延后。
- 本机 API 通过 SSH 隧道访问远程 PostgreSQL；Docker Worker 已通过 `backend/.env.worker` 和 `host.docker.internal` 连通同一隧道，执行 `SELECT 1` 已返回成功。
- Redis、MinIO 与仅监听 `document-processing` 的 Linux RQ Worker 继续由 `docker-compose.infrastructure.yml` 管理。

### 阶段 3.0：依赖与最小可运行闭环

1. 审核并新增仅用于 PDF、DOCX、TXT、Markdown 解析和本地 `bge-m3` Embedding 的依赖；不引入 OCR、云端 Embedding 或聊天续流依赖。
2. 增加配置项和健康检查，明确对象存储、Worker 数据库连接、Embedding 模型目录与处理限制；敏感值只保留在本地环境文件。
3. 先用无副作用 RQ 任务及数据库连通性测试确认 Worker 运行环境，再加载解析与 Embedding 模型。

验收：Docker Worker 能消费 `document-processing` 任务、访问远程 PostgreSQL 与 MinIO；失败日志可定位，聊天请求不进入该队列。

### 阶段 3.1：数据模型与私有资料树

1. 通过 Alembic 新增知识节点、文件版本、处理任务、文本分块和智能体资料范围关联表，以及必要的用户、父节点、状态与向量索引。
2. 实现 Repository 层的用户归属过滤、资料树查询、文件状态更新、分块批量写入和资料范围展开；路由及工作流节点不得直接写 SQL。
3. 实现文件夹创建、资料树读取、文件元数据读取和失败任务重试的 Service/API 骨架。

验收：迁移可升级；跨用户、跨智能体、删除节点及非法父节点均被拒绝；仅 `ready` 文件可被后续检索。

### 阶段 3.2：上传、对象存储与异步状态机

1. 前端新增知识库入口、资料树、上传区域与处理状态展示；配置页仅在后端范围能力可用后开放选择。
2. API 在请求内完成认证、格式/大小/空文件校验、元数据创建和 MinIO 私有对象写入，然后投递文档任务并立即返回 `uploaded/processing` 状态。
3. Worker 按 `uploaded → processing → ready/failed` 推进；重试必须清理旧分块和旧向量，避免重复索引。

验收：PDF、DOCX、TXT、Markdown 均能上传；越权读取、空文件、错误格式、超限文件和对象存储失败均有稳定结果；刷新页面仍能看到处理状态。

### 阶段 3.3：解析、切分与本地向量化

1. 将格式解析分别放在文档解析模块：PyMuPDF、`python-docx` 和纯文本读取；扫描版 PDF、图片和无可提取文本的文件进入 `failed`，不伪造内容。
2. 使用可配置、可测试的切分服务生成带来源位置的分块；保存文件、页码/段落、顺序和文本哈希。
3. Worker 批量调用本地 `bge-m3`，将向量、模型名和分块元数据写入 pgvector；Embedding 模型在 Worker 进程内缓存，不在 API 中加载。

验收：四种支持格式均产生可追溯分块；失败重试不重复写入；最小样本可按语义召回正确资料。

### 阶段 3.4：资料范围、检索与 LangGraph 接入

1. 实现 AI 管家“全部资料”开关与个人智能体文件/文件夹范围选择；文件夹范围递归包含未来新增后代。
2. 在独立 Retrieval Service 中先校验用户、智能体和范围，再检索 `ready` 分块并生成受控上下文和来源对象。
3. 将“加载会话上下文 → 解析资料范围 → 检索 → 构造提示词 → 模型生成 → 保存回答与引用”编排为线性 LangGraph；上传与 Embedding 仍不进入该图。
4. 保持聊天使用直接 SSE；检索命中、无命中、引用和模型失败均映射为既有流式事件，不重新实现断线续流。

验收：模型无法访问未授权资料；关闭资料开关或无命中时不伪造引用；每条引用可回到用户有权访问的文件和分块。

### 阶段 3.5：质量、性能与浏览器验收

1. 补齐迁移、Repository、Service、Worker、解析、检索、范围隔离和 SSE 引用事件测试。
2. 执行 Python 编译/测试、前端类型检查/构建，以及真实 MinIO、Worker、pgvector 的小样本集成测试。
3. 由浏览器验收：上传、处理进度、失败重试、范围选择、检索问答、引用、跨用户隔离、停止生成与普通无资料聊天。

完成条件：验收标准有可复核证据；图片/OCR、联网搜索和 Redis/RQ 聊天续流继续保持在后续独立阶段。

## 实施原则

- 每个阶段开始前，在开发记录中说明目标、模块、方案原因、风险和验证方式。
- 每阶段结束后只按实际验证结果更新状态，不把未联调功能标记为完成。
- 路由只处理 HTTP；业务规则在 Service；SQL 在 Repository；LangGraph 节点只编排 Service。
- 每次数据结构变化都通过版本化迁移，禁止继续向启动初始化函数追加业务表 DDL。

## 阶段 1：运行基础设施与数据迁移

### 目标

建立能安全承载后续业务的配置、迁移、对象存储、任务队列和模型适配边界。

### 涉及模块

- `backend/core`、`backend/integrations`、`backend/repositories`、`backend/workers`。
- PostgreSQL/pgvector、MinIO、Redis、DeepSeek、`bge-m3`。

### 实施步骤

1. 引入版本化迁移工具，为现有认证表建立基线，再创建智能体与知识库业务迁移。
2. 将数据库连接、对象存储、Redis、DeepSeek 与 BGE 配置集中到类型化配置模块；仅记录环境变量名称。
3. 封装对象存储、Redis 任务投递、DeepSeek Chat Model、BGE Embedding 的适配接口，并提供本地开发错误提示。
4. 建立 Worker 进程入口和任务状态模型；此阶段只验证任务可投递和执行，不实现完整解析流程。

### 选择理由

这些依赖是会话、文件和 RAG 的共同基础。先建立边界可以避免把第三方 SDK、密钥和网络错误散落到路由或工作流节点中。

### 风险与验证

- 风险：本地 Docker/服务未启动、模型权重下载失败、Windows 环境依赖差异。
- 验证：迁移可在空数据库升级；健康检查能识别必要服务；Worker 能执行无副作用测试任务；配置缺失时错误可定位。

## 阶段 2：智能体、默认打开与会话数据层

### 目标

完成 AI 管家、个人智能体、默认打开和“当前智能体会话隔离”的数据库与 API，不接入真实模型。

### 实施步骤

1. 创建智能体、偏好、会话、消息和引用表及索引；写入内置 AI 管家种子记录。
2. 实现 Repository 与 Service 的所有权校验、默认设置事务和软删除。
3. 实现 API-001 至 API-007，并用回显/测试回答验证会话读写。
4. 实现智能体列表、配置、默认打开和会话侧栏前端页面；先用普通消息渲染验证交互。

### 后端/AI说明

此阶段不需要 LangGraph。先验证“用户 A 永远不能看到用户 B 的资源”“每个智能体只显示自己的会话”这两个最重要的业务边界；AI 流程将在阶段 4 接入。

### 风险与验证

- 风险：软删除后默认设置和旧会话状态不一致。
- 验证：多用户越权接口测试、并发设置默认测试、软删除数据保留测试、前端构建。

## 阶段 3：文字资料与本地向量索引

### 目标

实现 PDF、TXT、DOCX、Markdown 的个人资料树、异步处理和 `bge-m3` 向量写入。

### 实施步骤

1. 创建资料节点、文件版本、处理任务、分块和资料范围关联表。
2. 实现文件夹、上传、状态查询和失败重试 API；原文件写入私有 MinIO bucket。
3. Worker 提取文字：PDF 使用 PyMuPDF，DOCX 使用 `python-docx`，TXT/Markdown 使用本地读取。
4. 使用 LangChain 文本切分器切分内容，Worker 本地调用 `bge-m3` 批量生成向量，写入 pgvector。
5. 实现智能体文件/文件夹范围配置与递归展开；验证新文件自动进入已选文件夹范围。

### 后端/AI说明

`bge-m3` 只负责“把文字转为向量”，不生成回答。上传处理必须放 Worker，因为模型加载、解析和批量向量化会阻塞 Web 请求。

### 风险与验证

- 风险：文档解析异常、BGE 内存不足、重复任务写入重复分块。
- 验证：四种格式处理测试、失败重试测试、文件夹自动纳入测试、向量检索最小集测试。

## 阶段 4：LangGraph RAG 聊天与流式界面

### 目标

接入 DeepSeek、LangChain、LangGraph、SSE 和 Ant Design X，完成真实可引用的 RAG 问答。

### 实施步骤

1. 实现固定图：加载会话上下文 → 检索允许分块 → 生成回答 → 保存结果。
2. 用 LangChain 适配 DeepSeek 和 `bge-m3`；检索前由 Service 完成用户、智能体与资料范围校验。
3. 用 FastAPI 将 LangGraph 事件转换为 SSE，支持状态、token、引用、完成和错误事件。
4. 用 Ant Design X 的 `Welcome`、`Prompts`、`Bubble`、`Sender`、`Conversations`、`Sources` 与流式 Markdown 渲染聊天页。
5. 完成取消生成、无召回、模型失败和引用展示。

### 后端/AI说明

LangGraph 只编排固定流程；它不自行选择数据库、文件或工具。DeepSeek 只接收后端已经授权的少量检索文本，因此模型不能越过资料范围。

### 风险与验证

- 风险：SSE 中断、模型超时、引用与最终回答不同步。
- 验证：流式接口测试、取消测试、越权资料不进入模型上下文测试、浏览器端到端测试。

## 阶段 5：质量、性能和验收

### 目标

依据 `AC-001` 至 `AC-017` 完成跨层验证，并处理首期上线前风险。

### 实施步骤

1. 执行 Python 类型/编译、前端类型/构建、服务单元测试、接口测试和文件处理集成测试。
2. 使用真实但非敏感样本资料验证召回、引用、延迟和失败恢复。
3. 评估 pgvector 索引：先精确检索，数据规模达到阈值后基准测试 HNSW。
4. 审查日志、对象存储权限、环境变量、错误信息和跨账号访问边界。

### 完成条件

所有已确认验收项有对应验证证据；未验证或明确延期的项保留在项目状态和开发日志中。
