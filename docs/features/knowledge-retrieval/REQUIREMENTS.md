# 功能需求

## 1. 功能目标

让已授权智能体仅从其资料范围内的已就绪文件召回内容，为聊天回答提供可追溯引用。

## 2. 功能范围

### 本次包含

- 按标题/段落/列表/表格语义边界优先、token 上限强制拆分与重叠的混合切分。
- 独立 `embedding` RQ Worker 本地运行 `BAAI/bge-m3`，进程内懒加载单例和持久化模型缓存。
- 候选召回同时使用向量相似度和关键词匹配，分别取候选后融合排序；候选阶段不直接作为模型上下文。
- 使用本地 `BAAI/bge-reranker-v2-m3` 对融合后的候选分块进行重排，只有重排分数达到阈值的分块可以进入上下文。
- 每个文件最多向模型提供 2 个分块，最终最多 5 个分块、3 篇文件；避免一份长文档或弱相关文件垄断上下文。
- 强制按当前用户、`ready` 状态、智能体文件/文件夹递归范围过滤。
- 引用仅展示最终送入模型上下文的来源；运行步骤的“命中”使用最终采用的文件数与分块数，不能将候选分块称作资料篇数。
- 保存每次检索的候选分数、重排分数、淘汰原因和最终上下文来源，供排查误召回。
- 文档更新使用异步版本化重建；删除立即排除检索，后台清理向量与对象。

### 本次不包含

- OCR、跨用户共享、全库重建、外部 Embedding API、联网检索。

## 3. 核心流程

1. 文档解析完成后投递 embedding 任务。
2. Worker 切分、批量向量化并写入新版本索引。
3. 新版本完整成功后原子切换为可检索版本；失败不影响旧版本。
4. 知识库模式聊天先检查智能体资料范围内是否存在 ready 索引文件；存在时每个问题都检索候选，不由模型决定是否跳过检索。
5. 向量与关键词候选融合后，由本地重排模型判断分块是否能回答问题；按重排分数、文件限额和上下文上限确定最终来源。
6. 若没有 ready 索引文件，返回“当前资料范围没有已完成索引文件”；若最终没有足够相关内容，返回“当前知识库未找到相关内容”，两种情况均不生成通用模型回答。
7. 模型只在存在最终有效来源时回答，回答与实际使用的来源关联，前端展示同一组文件与可追溯定位。

## 4. 边界规则

- 无命中时正常聊天，不伪造引用。
- 知识库模式中，无命中不得回退为未引用的通用模型回答。
- 相同候选文件不因多个弱相关分块而获得不成比例的上下文份额。
- 任一文件出现在最终引用中时，必须有至少一个经过阈值筛选的分块实际传入模型上下文。
- 模型、向量库或 Worker 失败时记录可定位错误并返回降级结果。
- 删除请求成功后，该文件立即不得再被检索命中。
