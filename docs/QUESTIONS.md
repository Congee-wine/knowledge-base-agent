## Q-20260729-017：是否向用户披露底层模型信息

- **日期**：2026-07-29
- **状态**：已确认
- **涉及模块**：智能体运行、LangGraph、系统提示词、安全边界
- **用户问题**：智能体是否适合回答其背后调用的模型；要求模型信息对用户隐藏。
- **最终结论**：不向用户披露模型供应商、名称、版本、知识截止日期或任何内部技术配置。身份和能力问题由服务端公开档案固定回答，不能由模型自由生成。
- **实现影响**：新增 LangGraph 身份守卫和后端公开身份档案；敏感问题绕过模型调用，普通模型输出增加保密约束与泄露兜底。
- **后续事项**：新增能力时同步更新公开档案，确保其只描述真实已启用能力。

## Q-20260729-016：智能体在知识库无结果时应如何处理

- **日期**：2026-07-29
- **状态**：已确认
- **涉及模块**：智能体运行、LangGraph、检索、聊天 SSE、提示词
- **用户问题**：当前固定检索流程在知识库没有相关资料时直接要求用户更换问题，无法像真实可用智能体一样理解问题、判断下一步并利用大模型完成回答。
- **问题背景**：检索是获取私有依据的工具，不应成为正常问答的唯一前提；不同问题对私有资料、通用知识和澄清提问的依赖不同。
- **最终结论**：采用服务端受控的策略工作流。智能体先分析问题，再选择直接回答、知识库回答、混合回答或澄清；无检索结果时，对可安全使用通用知识回答的问题必须继续回答，仅在用户明确要求私有资料依据且证据不足时说明缺少内容并提出具体补充建议。
- **实现影响**：重构 `agent_runtime` 的固定检索顺序，新增策略和证据评估边界；SSE 只展示可验证的执行摘要，不展示模型原始思维链；补充策略、降级、权限隔离和引用真实性测试。
- **后续事项**：在完成策略设计后实现受控决策节点，并通过真实会话场景验证。

- **实现影响**：新增 `backend/requirements.worker.txt`，修改 `backend/Dockerfile.worker`；不影响 API、数据库或主后端依赖。

## Q-20260727-013：流式完成后为何会重复显示首条问答

- **日期**：2026-07-27
- **状态**：待浏览器验收
- **涉及模块**：流式聊天 Hook、会话详情缓存、聊天页面消息合并
- **用户问题**：新会话首条消息在助手流式回复完成后，会再次出现相同的用户和助手消息。
- **问题背景**：本地流式消息和 React Query 中重新获取的服务端详情消息同时参与渲染；二者先前使用不同 ID，且缺少“服务端已确认后再移除本地副本”的边界。
- **最终结论**：`message_start` 必须将本地临时 ID 替换为服务端真实 ID；消息渲染按真实 ID 去重，完成事件仅记录待确认消息对，确认详情缓存含有该消息对后才清理本地副本。每次发送前还必须清空上一请求的真实 ID，防止新请求早期失败误伤上一条助手消息。
- **实现影响**：影响 `frontend/src/api/chat.ts`、`frontend/src/features/chat/hooks/useStreamingChat.ts`、`frontend/src/features/chat/utils/mergeMessages.ts`、`frontend/src/pages/ChatPage.tsx` 及对应单元测试；不改变后端接口、数据库或迁移。
- **后续事项**：在浏览器中验证新会话首条问答、已有会话续发、服务端详情刷新滞后和请求早期失败四种场景。

- **用户问题**：用户消息和助手消息的创建时间相同，导致助手消息有时显示在用户消息上方。

## Q-20260725-011：是否展示模型推理与工具执行轨迹

- **日期**：2026-07-25
- **状态**：已确认
- **涉及模块**：DeepSeek 运行适配、预览聊天、正式聊天、知识库检索、联网工具、文件处理
- **用户问题**：模型思考链是否自带；知识库搜索、文件解析和联网等步骤是否应该展示在思考过程中；后续补充是否容易。
- **问题背景**：模型推理、检索、联网和文件处理具有不同的数据来源、可靠性和生命周期。将它们都作为自由文本“思考链”展示会混淆模型中间推理与可验证的系统动作。
- **最终结论**：采用简短、受控的处理思路摘要，但将其放在阶段 D；阶段 A 先实现流式最终答案和简单生成状态，阶段 B/C 再接入真实执行步骤与引用。知识库、联网和文件处理不展示模型完整原始思维链。
- **实现方式**：从共享运行服务开始预留最终回答和执行事件边界；阶段 B/C 增加 `executionSteps` 与引用，阶段 D 再增加 `reasoningSummary`。正式会话只持久化后续确认需要保存的摘要和执行事件，预览仅保留在内存。
- **实现影响**：若确认，需要在流式阶段定义 SSE 事件和消息扩展结构；阶段 A 的文本问答仍可先完成。
- **后续事项**：确认是否需要展示供应商的推理摘要、展示粒度和历史保存策略。

## Q-20260725-010：智能体配置为何在编辑预览和其他入口不一致

- **日期**：2026-07-25
- **状态**：已解决，待浏览器验收
- **涉及模块**：智能体编辑、列表、导航、聊天欢迎区、React Query 缓存
- **用户问题**：已设置的头像和名称在编辑页顶部、右侧预览、侧边栏和卡片中出现不同结果；右侧预览没有复用真实聊天输入栏。

- **最终结论**：所有展示入口使用共享头像与自建欢迎组件；编辑草稿按字段合并，保存结果同步写回详情、列表和默认入口缓存。AI 管家与自建智能体保持不同欢迎视觉，前者问题由数据库读取。
- **实现影响**：新增共享展示组件和内置问题种子迁移；不新增 API。
- **后续事项**：实际应用迁移，并在浏览器检查头像上传后保存、预设问题和入口开关同步。

## Q-20260724-009：为什么热更新后会跳转登录页

- **日期**：2026-07-24
- **状态**：已解决
- **涉及模块**：前端认证恢复、Vite 热更新、路由守卫
- **用户问题**：开发过程中页面突然跳转登录页，后端认证接口日志仍显示成功响应。
- **问题背景**：Vite 编译错误或整页重载可能中断正在进行的刷新请求；旧实现将任意刷新失败都当作登录失效，直接删除浏览器会话。
- **最终结论**：仅服务端明确返回 401/403 或本地缺少刷新令牌时清除会话。网络错误、请求取消和热更新中断保留 token；整页重载时可使用已保存的用户摘要维持受保护路由，等待服务端确认。
- **实现影响**：`frontend/src/lib/auth.ts`、`frontend/src/App.tsx`。
- **后续事项**：在 Vite 热更新期间人工验证认证状态保持。

## Q-20260723-008：为什么本地 HTTP 请求持续缓慢

- **日期**：2026-07-23
- **状态**：已解决
- **涉及模块**：FastAPI 生命周期、PostgreSQL、认证、Repository
- **用户问题**：感觉每次 HTTP 请求都有明显响应延迟，希望确认原因。
- **问题背景**：健康检查约 6ms，但每次 `psycopg.connect()` 实测约 491–719ms；受保护接口在认证和业务查询中会多次建立连接。
- **最终结论**：主要瓶颈是反复建立 PostgreSQL 连接。采用共享 Psycopg 连接池后，池借还实测约 0.02ms；同连接查询仍存在约 70–230ms 延迟，后续按 SQL 数量、索引和本机网络继续分析。
- **实现影响**：新增 `psycopg_pool`、连接池配置和 FastAPI 生命周期管理；不改变业务 API 或数据库 schema。
- **后续事项**：上线前依据 API 进程数与 PostgreSQL 最大连接数设置池上限，并增加请求/SQL 耗时观测。

## Q-20260723-007：新会话何时持久化

- **日期**：2026-07-23
- **状态**：已确认
- **涉及模块**：聊天页面、会话 API、会话持久化
- **用户问题**：点击“新会话”会先请求接口且产生空历史记录，希望首次输入并发送时再创建会话，并为后续 AI 流式回复保留这一流程。
- **问题背景**：点击即创建使界面产生等待，且用户没有发送内容也会留下无意义的会话。
- **最终结论**：新会话为前端本地空白状态，不调用创建接口；首次发送不带 `conversationId`，后端以单个事务创建会话和消息。后续 SSE 复用相同的首次发送语义。
- **实现影响**：新增统一消息接口；前端新会话不刷新历史列表；会话仅在首条消息成功后出现。
- **后续事项**：模型与 SSE 接入时补充流式事件和取消策略。
